\section{PART 1 --- FTP Protocol Analysis (Phân tích giao thức FTP)}

\subsection{Tổng quan \& Môi trường thử nghiệm}
Giới thiệu tổng quan về giao thức FTP, mô hình thử nghiệm với Public FTP Server (\texttt{ftp.dlptest.com}) và hệ thống FTP Client/Server tự phát triển từ Project 01 chạy trên 2 máy PC riêng biệt.

\subsection{Phân tích phiên 1: Public FTP Test Server (ftp.dlptest.com)}
  \subsubsection{Thí nghiệm 1: Khởi tạo kết nối FTP (Establish Connection)}
  Trình bày chi tiết quá trình bắt tay 3 bước TCP (SYN, SYN-ACK, ACK), địa chỉ IP nguồn/đích và số hiệu cổng điều khiển 21.

  \subsubsection{Thí nghiệm 2: Xác thực đăng nhập (Login Authentication)}
  Phân tích gói tin chứa thông tin tài khoản \texttt{USER} và \texttt{PASS} truyền dạng rõ (cleartext) và thông điệp phản hồi 230 từ Server.

  \subsubsection{Thí nghiệm 3: Xem danh sách thư mục (Directory Listing)}
  Phân tích lệnh \texttt{LIST}, kênh truyền dữ liệu (Data Channel) và cổng kết nối liên quan.

  \subsubsection{Thí nghiệm 4: Upload File (Upload a File)}
  Phân tích lệnh \texttt{STOR}, thời gian truyền dữ liệu và phản hồi hoàn tất 226.

  \subsubsection{Thí nghiệm 5: Download File (Download a File)}
  Phân tích lệnh \texttt{RETR}, dung lượng file, stream TCP chứa dữ liệu và cơ chế Active/Passive Mode.

\subsection{Phân tích phiên 2: Hệ thống FTP Client/Server từ Project 01 (2 PCs)}
  \subsubsection{Kết quả thực nghiệm trên 2 máy PC thực tế}
  Trình bày các minh chứng gói tin thu thập được khi chạy phiên FTP giữa 2 máy PC thực tế.

\subsection{Thảo luận \& Đánh giá mở rộng (Discussion \& Analysis)}
  \subsubsection{So sánh chi tiết Active Mode vs Passive Mode}
  Phân tích nguyên lý hoạt động của lệnh \texttt{PORT} (Active) và \texttt{PASV} (Passive), sự khác biệt về bên khởi tạo kết nối dữ liệu.

  \subsubsection{Đánh giá an toàn thông tin đối với FTP}
  Đánh giá rủi ro lộ mật khẩu khi truyền plaintext và đề xuất các giải pháp bảo mật thay thế (FTPS / SFTP).

  \subsubsection{So sánh đối chiếu giữa 2 phiên thực nghiệm (Test Server vs Project 01)}
  So sánh điểm tương đồng và khác biệt giữa Server thực tế trên Internet và Server tự cài đặt trên mạng nội bộ.

\section{PART 2 --- HTTP Protocol Analysis (Phân tích giao thức HTTP)}

\subsection{Chương trình Socket Client (Part A --- Socket Client Code)}
  \subsubsection{Mã nguồn chương trình (\texttt{http\_client.py} / \texttt{http\_client.c})}
  Trình bày đoạn mã nguồn lập trình Socket thô kết nối đến cổng 80 của target host.

  \subsubsection{Giải thích chi tiết các bước xử lý trong Socket Code}
  Giải thích chi tiết từng lệnh khởi tạo socket, thiết lập kết nối TCP, tạo chuỗi HTTP GET request và đọc dữ liệu response.

\subsection{Bắt gói tin Wireshark (Part B --- Packet Capture)}
  Trình bày cấu hình capture filter \texttt{tcp port 80} và quá trình lưu file \texttt{lab\_capture.pcapng}.

\subsection{Trả lời các câu hỏi phân tích chi tiết (Part C --- Analysis Questions)}

  \subsubsection{A. Name Resolution \& Addressing (Phân giải tên miền \& Địa chỉ)}
  Trả lời Câu 1 -- 2 về truy vấn DNS và địa chỉ IP kết nối.

  \subsubsection{B. The TCP Connection (Kết nối TCP)}
  Trả lời Câu 3 -- 6 về bắt tay 3 bước TCP, Source Port, thông số MSS, Window Size và thời gian RTT.

  \subsubsection{C. The HTTP Request (Yêu cầu HTTP)}
  Trả lời Câu 7 -- 9 về phương thức HTTP GET, các dòng Header và dung lượng Request.

  \subsubsection{D. The HTTP Response (Phản hồi HTTP)}
  Trả lời Câu 10 -- 14 về Status Code (301 Redirect), Location header, Response headers và dấu hiệu kết thúc Message Body.

  \subsubsection{E. TCP Segmentation \& Reassembly (Phân đoạn \& Tái hợp dữ liệu TCP)}
  Trả lời Câu 15 -- 20 về cơ chế phân đoạn TCP theo MSS, Sequence Number, ACK Number và quá trình tái hợp dữ liệu của Wireshark.

  \subsubsection{F. Closing the Connection \& Totals (Đóng kết nối \& Tổng kết dữ liệu)}
  Trả lời Câu 21 -- 22 về các gói tin FIN/RST ngắt kết nối và so sánh tổng lượng byte gửi/nhận.

  \subsubsection{G. Reflection (Đánh giá \& Nhìn nhận)}
  Trả lời Câu 23 -- 24 về vấn đề bảo mật của HTTP (Port 80) vs HTTPS (Port 443) và tóm tắt vòng đời đầy đủ của một HTTP Request.
